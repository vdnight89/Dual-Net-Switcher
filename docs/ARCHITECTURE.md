# 双网卡管家设计决策

## 使用与边界

双击启动入口 → 查看真实网卡 → 选择主出口和专用出口 → 编辑规则并保存 → 预览 → 应用。普通启动可编辑和预览；管理员入口通过 Windows UAC 启动，以后由该进程执行应用、恢复和同步。

`Manager.save(config, revision)` 只保存草稿；`preview()` 读取系统并解析；`apply(planId)` 检查配置和网卡仍与预览一致后提交；`reset()` 只恢复系统执行器登记的资源；`tick()` 只同步最近成功应用的配置。无 GUI 控件可直接调用 Windows 命令。

## Arena 决策

两份同模型独立候选及交叉评审在 `arena/`。主代理评分（依次为恢复、DNS、简洁、幂等、测试，满分10）：A=9/9/8/8/9，加权86；B=8/8/9/8/8，加权82。交叉评审 A=87、B=83.5，同样推荐 A。

采用 A：原生 Node HTTP 与独立 PowerShell Windows 边界。引入 B 的“自动同步只使用已应用配置”约束。拒绝 WinForms 为本次主界面，理由是当前机器已安装 Node，浏览器界面的维护和自动化验收更直接；保留参考项目，不复用其硬编码公司规则。不是多模型评审。

## 模块与所有者

- `model.mjs`：配置边界验证、URL/Host/IP/CIDR 归一化、冲突与期望资源。
- `manager.mjs`：唯一配置写者、已应用策略、串行队列、DNS 刷新、计划有效期。
- `windows.mjs` / `windows.ps1`：固定 JSON 协议；唯一系统资源、所有权和事务写者。
- `server.mjs`：仅回环地址，严格 Host/Origin、随机令牌、JSON 请求、防静态目录穿越，无命令执行接口。
- `public/`：三页签工作台，只调用业务接口；文本安全渲染。

配置存 `data/config.json`，成功应用策略和最近成功解析存 `data/runtime.json`。系统资源与事务的文件由 PowerShell 单独管理。演练使用 `data/demo/`，永不调用 Windows 写入能力。

## 已明确收缩的设计

不实现首次 DNS 的两阶段自举事务：预览只读查询，如所选 DNS 无法经指定源地址访问，则阻止应用；用户可以先仅启用 DNS 所在网段规则并应用，然后启用域名规则。这样不会为预览偷偷改网，也不会产生两次提交间的所有权空洞。正常可达的网卡 DNS 支持自动解析、TTL、A 记录刷新；最终计划为 DNS 添加精确路径。

HTTP 的随机启动令牌存 URL fragment，页面转存 sessionStorage 并清掉地址 fragment；API 必须传自定义认证头，精确校验 Host/Origin，跨站预检没有 CORS 响应。本版没有额外的 HttpOnly cookie 换票层；保持单用户本地工具的一个认证方式。`data/session.json` 包含本机管理入口，不可公开分享。

网卡以 GUID 持久识别，实际写入前重读索引。不会把有线网卡视为已经验证可上公网；主出口由用户选择。仅 IPv4；IP 路由无法区分共享同一 IP 的域名。DoH、代理、VPN 的覆盖由各自行为决定，工具不修改它们。

Windows 补偿事务不具备数据库级原子性；回滚失败保留恢复信息并停止后续应用，不显示虚假成功。当前开发验证不修改宿主机路由；真实写入验收需隔离 Windows 环境或用户在界面应用。

## 用户修订后的按需进程架构

用户明确仅 PC，并要求小体积、低内存、尽量不常驻。保留原生 Node/PowerShell，取消必须保持管理进程的前提：静态路由和 NRPT 由系统持有；后台维护使用 Windows 计划任务，在登录和配置周期调用隐藏的固定维护脚本，执行 `--sync-once` 后退出，不建立 HTTP 监听。

管理进程和一次维护共用 PID 实例锁；管理进程存活则任务跳过，由已有管理进程维护。Windows mutex 继续保护系统事务。退出管理等待在途业务写操作完成后释放锁并退出。未应用配置或已暂停维护的一次任务只读文件即退出。

系统应用和恢复之前，先原子持久化 maintenanceSuspended 意图；只有系统执行成功且新应用策略落盘后才解除。这样崩溃不会让较旧的成功策略自动撤销一次新应用或重置。下次明确应用/恢复可解除暂停。

为避免误停其他同名 Node 脚本，UAC 重启与停止入口通过带随机令牌的本机身份接口核对项目绝对路径和 PID；同时验证监听端口所属进程。后台任务通过完整任务定义和 SID 规范化保护所有权。
