`node --expose-gc scripts/measure.mjs` 只做真实网卡读取和无策略维护，不改网络。测量管理进程自身，不包括浏览器和瞬时 PowerShell 子进程。最新数值见 `evidence/performance.json`：Node RSS 约 55.5 MiB、JS 堆实际使用约 6.9 MiB；启动真实网卡探测约 4.3 秒。未配置策略的一次维护在现有 Node 进程内跳过逻辑约 2ms，不包含操作系统启动 Node 的开销。

退出管理后无本工具服务进程；计划任务每次启动临时进程并退出，不能把任务执行期间描述为零内存。实际 DNS、系统写入耗时取决于网卡和服务器。无前端依赖、构建产物、第三方字体、图片下载；便携 ZIP 不包含 Node 运行时、参考项目、数据、截图和视频。

## 2026-10-20 真实双网卡集成验收（有线 Home-Router + 无线 Corp-WiFi）

测试环境：以太网 192.168.1.123（网关 192.168.1.1，metric 5）、WLAN 192.168.144.67/21（网关 192.168.151.254，metric 5000，SSID Corp-WiFi），测试保护保持 armed。真实配置：4 条内网规则（btos.example.com、oa.example.com 两个域名 + 172.18.28.50、172.18.20.83 两个 IP），专用出口 DNS 172.30.1.1。

前置只读验证：产品自动识别两网卡并正确分配主/专用出口；绑定源测试证实内网 DNS 172.30.1.1 仅经 WLAN 可达（3ms），经有线 100% 丢包；两个 IP 目标经 WLAN 有响应（403/302）、经有线超时。

应用与恢复实测：预览生成的路由计划与设计一致（默认出口借用以太网 DHCP 路由 metric 0；域名 A 记录与 DNS 查询路径为活动 /32；IP 规则为持久路由；NRPT 精确域名指向 172.30.1.1）。真实应用后 route print 确认 5 条活动 /32 + 2 条持久路由全部经 WLAN 网关；NRPT 2 条生效；所有权记录 7 路由 + 2 NRPT。系统级验证（不经手工绑定源）：四个目标全部可达（403 / 302 / 200 / 302），域名经 NRPT 由 172.30.1.1 解析；默认公网出口保持有线（baidu/qq 正常）。恢复实测：reset 后 172.18/172.30/10.169 路由、NRPT、持久存储全部清零，借用默认路由保留，内网目标回到不可达，随后重新应用成功并复核。

本机实机测试发现并修复 4 个演练无法暴露的问题：

1. `lib/windows.mjs` validatePlan 拒绝 RouteMetric 0，导致借用默认路由（metric 0）无法应用。已允许路由 metric 0–9999 并补回归测试。
2. 本机 Windows 26200 的 CIM 拒绝 `New-NetRoute/Set-NetRoute -PolicyStore PersistentStore`（Invalid parameter）。持久路由改用 `route.exe -p add`（一次写入持久+活动两个存储，覆盖式更新），并新增输出文本失败检测——route.exe 会在打印"路由添加失败"时仍返回 exit 0。诊断证据：`logs/route-diag*.json`。
3. `Get-DnsClientNrptRule` 返回的 NameServers 是 System.Net.IPAddress 对象而非字符串，导致写后校验与回滚漂移判断必然失败（真实回滚曾因此中断并进入恢复保护状态，恢复入口自愈）。已在 Read-Resource 归一化为字符串。
4. 持久路由前缀拆分曾把数组强转为字符串导致地址截断为单字符，已改为 `[string[]]($prefix -split '/')`。

其他实测发现（未全部处置）：内网 DNS 172.30.1.1 延迟双峰（约 10ms 或 >3s），偶发连续超时使预览失败，重试即恢复；已将解析器默认 timeout 3000/tries 2 放宽为 8000/tries 3（对运行中实例需重启生效）。内网 DNS 对两个域名均返回第二个 A 记录 172.30.9.1，该地址实测不可达（经 WLAN 直连也超时），属 DNS 侧数据质量问题；命中该地址的连接会失败，待域名解析收敛或后续按需为该地址补路由。PS 5.1 排序不稳定会使持久路由资源的应用顺序与计划列表不同，不影响正确性。

新功能：网卡下拉与设置页现在显示网络名（WiFi 取 SSID，如 Corp-WiFi；有线取网络配置文件名，如 Home-Router），来自快照新增的 adapter.networkName 字段（netsh SSID 优先，Get-NetConnectionProfile 回退）。
